# 🎮 Games

A collection of browser-based digital tabletop and classic games built using **HTML, CSS, and JavaScript**.

The project is designed to be lightweight, responsive, and playable directly from a web browser without requiring installation.

---

## 🕹️ Games

### ♟️ AstaChamma
A digital implementation of the traditional Indian board game AstaChamma.

**Features:**
- Multiple players
- Custom game board
- Dice/coin-based movement system
- Safe zones
- Piece movement and elimination
- King and Knight pieces
- Animated gameplay
- Multiple visual themes

---

### 🐍 Snake & Ladder
A digital version of the classic Snake & Ladder board game.

**Features:**
- Classic 100-square board
- Snakes and ladders
- Player movement animation
- Computer player
- Multiple players
- Dice-based movement
- Win detection
- Animated board elements

---

### 🎟️ Tambola
A browser-based Tambola/Housie number caller.

**Features:**
- Numbers 1–90
- Random number drawing
- Number history
- Recent numbers
- Voice announcements
- Multiple themes
- Sound effects
- Game statistics
- Persistent preferences

---

### ❌⭕ Tic-Tac-Toe
A modern Tic-Tac-Toe game with local AI.

**Features:**
- Player vs Player
- Player vs AI
- Perfect-play Minimax AI
- Score tracking
- Draw detection
- Winning-line highlighting
- Themes
- Sound effects
- Animations
- Configurable game settings



---

## 🌐 Playing the Games

The games are standalone web applications and can be played directly in a modern browser.

### Launch

Open:

```text
index.html
```

Or visit

[Games](https://rachakonda-ravi.github.io/Games)

The main page provides access to the available games.

## 🚀 Deployment

The project is designed to work with GitHub Pages.
Because the games are client-side applications, no server is required for the standard game modes.

---

## 🤖 Tic-Tac-Toe AI

Tic-Tac-Toe currently includes a local Minimax AI.
The planned True AI mode will allow a player to provide their own API key and use an external AI service as the opponent.

- The API key will not be included in the repository.
- For security reasons, API keys should never be hard-coded into the source code or committed to Git.
